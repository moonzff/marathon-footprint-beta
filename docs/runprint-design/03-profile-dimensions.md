## 三、字段级数据模型草案（伪 schema）

设计原则：**原始事件（RaceResult）是唯一事实源；Profile 上的维度绝大多数是派生计算产物（derived），不重复存储。** 每条原始数据都挂一枚 `provenance`（来源血缘）+ `verification`（验证态），D5 不是独立表而是贯穿每个字段的"成色戳"。

```jsonc
// ========== 原子层：单场完赛事件（唯一事实源）==========
RaceResult {
  id, profileId,
  // — 赛事元数据（关联众包 RaceDict）—
  raceId,                    // → RaceDict（赛道难度/认证标/地标/气候带/线上线下）
  date, distanceMeters, discipline, // road|trail|ultra|tri|ocr|virtual
  elevationGainM,            // 越野双轴
  // — 成绩 —
  netTimeSec, gunTimeSec,
  splits: [{ km, paceSecPerKm }],   // 喂 D1.5/D4.2 配速派生
  overallRank, ageGroupRank, finishers,
  // — 每条关键字段独立挂成色戳（D5 贯穿）—
  provenance: { source, importedAt, raceTimestamp, crossRefs[] },
  verification: { tier },    // T0..T4，派生而非手填
  // — 用户自传附着（肖像红线：仅本人上传）—
  selfMedia: [{ type, url, exif, isPortraitOfOwner }],
  emotion: {                 // D10.1 完赛瞬间（手动，可空）
    finishQuote, moodTag, bodyKeywords, dedicationId? },
  gearUsedId,                // → Gear，喂 D3 + D11.1 战靴玄学
}

// ========== 实体层：用户主动维护的资产 ==========
Gear { id, profileId, category, brand, model,
       status, // active|retired
       mileageLedger, retiredAt, isPB, techGen, // 碳板代际
       provenance, verification }

Collectible { id, profileId, type, // medal|bib|tee|stamp|pin
              raceId, selfPhoto, rarityScore, phygitalStatus }

Membership { id, profileId, clubId, role, since, verifiedBy[] } // D7 双向确认

Relationship { id, profileId, targetProfileId,
               type, // buddy|mentor|family|paced
               confirmedBothSides: bool }     // 关系类强制双向

NarrativeEntry { id, profileId, raceId?, // 必锚定完赛ID（除少数）
                 type, // signature|comeback|why|milestone|dedication|transformation|charity
                 body, privacy, // default private for sensitive
                 verifiedClaim?: { source } }  // 公益/改变挂D5

WishlistItem { id, profileId, type, // race|time|city
               target, deadline, progress,
               fulfilledByRaceId? }           // 愿望→完赛自动闭环

ClaimedTag { profileId, tag, source } // 动机微调/记录者类型/仪式等认领档

// ========== Profile 主对象：薄身份壳 + 大量派生 ==========
Profile {
  id, displayName, joinedAt,
  identity: { realNameVerified, faceConsentEnabled: false }, // D5.4 默认关

  // —— 以下全部为 computed/derived，定时或事件触发重算 ——
  derived: {
    // D1 能力
    level: { caaGrade, vdot, percentiles{national,city,ageGroup,...} }, // computed
    pbMatrix: { road{}, trail{}, ultra{}, tri{} },        // from RaceResult
    runnerType: { enduranceSpeedAxis, signatureDistance, riegelIndex }, // computed
    contextAdjusted: { byCourse, byAltitude, byWeather },  // computed×RaceDict
    pacingProfile: { shape, disciplineScore, wallPoint },  // from splits, 与D4共享
    ageGrade, milestones[], progressionCurve[],            // computed

    // D2 履历
    counts: { total, byDistance{} },
    cumulative: { distanceKm, runningTenureYears, streakYears },
    footprint: { cities[], provinces[], countries[], continents[],
                 terrains[], landmarks[], extremes{N,S,E,W,highest} }, // computed极值
    collections: { majors, hundredMarathon, weatherBadges[], firstRace }, // 收集册引擎

    // D3 装备（聚合自 Gear/Collectible）
    brandAllegiance, kocStatus, gearInvestmentBand, // 区间化非精确额

    // D4 人格（全派生）
    primaryPersona, tagCloud:[{tag,state}], // hidden|developing|lit
    gritScore, motivationRadar{}, runType:{code,nickname,rarity},

    // D5 信用（贯穿聚合）
    developRate,         // T0+T1 占比
    careerCoverage,      // 防选择性晒：总场次vs展示场次
    crossPlatformConsistency,
    trustScore: { score, badge }, // 与水平解耦

    // D10 情感（元维度脊椎）
    storySpine: [ /* 按时间编织 RaceResult + NarrativeEntry */ ],
    yearInReview: [{ year, keyword, highlights }],

    // D11 玄学
    luckyShoe, luckyBib, homeRace, pbSuperstition{factor,evidence}, // PB玄学=交叉派生

    // D12 环境
    weatherConquests[], climateZones[], nightRunner, geoSpan,
  },

  // —— 显影/隐私落位（见第四节）——
  visibility: {
    publicHeroFields[],    // 首屏
    foldedFields[],        // 折叠
    privateFields[],       // 私域，永不公开
  }
}
```

**关键工程主张**：
- `verification.tier` 是**派生**的（由 provenance 交叉算出），不可手填——杜绝吹牛。
- `pacingProfile` 被 D1.5 和 D4.2 共享，**一份数据喂多维**（避免重复计算与定义漂移）。
- `pbSuperstition`、`runnerType`、`runType`、`storySpine` 都是纯 computed——它们是"惊喜引擎"，恰是**只有聚合平台给得出**的护城河兑现。
- 敏感字段（健康/金额/纪念）`privacy` 默认 private，且**不进任何排名/算法输入**。

## 四、维度落位规则：公开首屏 vs 折叠 vs 私域

落位由三条轴决定：**①偏向（晒>参>留）②验证成色 ③敏感度**。统一规则：

### 公开主页首屏（晒导向 · 已显影 · 正向）
- D1：等级勋章/跑力分、**切到正向群体的百分位**、破X成就、本命距离、年龄平权(大龄)
- D2：完赛总场次、累计里程(宏大类比)、城市足迹地图、首马故事、收集册进度
- D3："大神参考位"三件套——**在役鞋阵 + 主力表 + 补给方案**；奖牌墙、签名合影展柜
- D4：**主人设徽章 + RunType 物种**（入门也满）、已点亮正向标签、Grit Score
- D5：**Trust Score 封蜡章** + 分层徽章（一枚即懂）
- D10：完赛一句话、心愿单、生涯故事长卷入口、年度关键词
- D12：极端天气勋章、世界尽头坐标、奇观地标册（视觉海报素材天花板）
- **铁律**：第一屏永远先庆祝高光，任何"未达成"显示为进度环而非空白。

### 折叠层（参考导向 · 资深点开才看 · 中性）
- D1：弱项距离、配速衰减曲线、撞墙点、阈值速度、成绩语境化细节
- D5：**证据链抽屉**（来源/时间/交叉印证）、生涯覆盖率、跨平台一致性
- D6：训练结构、强度模型、配速谱、转化效率、备赛充分度
- D7：同场跑友网络、配速圈、师徒谱
- D10：意义赛vs刷分赛标注、初心演变
- 设计：默认折叠，盾形小图标点开"证据/诊断"二级页。

### 私域层（仅本人/明确授权 · 永不公开 · 不进算法）
- D5：T4 存疑/冲突、异常检测结果（绝不公开打假羞辱）
- D6：静息心率、完整心率分布、HRV、睡眠、训练负荷、易伤评分、**伤病史/康复状态**、跑姿对称性、GPS 起终点（住址脱敏）
- D3：装备总投入精确金额（公开仅区间/段位，可一键隐藏）
- D10：纪念性跑步(为某人)、人生改变(心理/健康)、康复弧线——**默认私密，公开需二次确认**
- D12：家庭关系成员关联（需双方授权）

## 五、反劝退/渐进披露的维度级设计（入门也有可晒维度）

这是产品对新人的情绪承诺，必须落到维度机制，不能只是口号：

1. **群体切片 + 年龄平权 = 数学化反羞辱**（D1.7）：不是"你跑得慢"，而是切到"30-34女子年龄段"找到"前30%"。**这是"绝不羞辱"的工程实现核心**，而非文案修饰。

2. **正向命名转译层**（D4 系统级基础设施）：所有负向信号过一层映射——慢→风景派/享受型、撞墙→勇敢出发型、关门→压线英雄/极限坚持、随性→自由灵魂。羞辱性原始值只在私密诊断视图给资深+配成长建议。

3. **RunType 即得身份**（D4.6）：入门首场即拿到完整、酷、正向的"物种身份"+图腾，零额外采集、不需几十场数据——**反羞辱杀手锏**。

4. **三态显影=收集游戏**（D4.1/D2.6）：标签分隐藏款/显影中/已点亮，"未达成"一律显示为进度条/倒计时（"再1场越野点亮越野控"），**永不显示空白或"你还不是X"**。

5. **入门专属的非成绩身份出口**：
   - D2 时空族——城市/跑龄/首马故事纯靠积累发光，"速度有人比你快，但你跑过的城市抢不走"
   - D7.3 志愿者 + D7.5 共同点信号——不靠成绩，靠善意/同城找到组织
   - D10.5 心愿单——"履历空"优雅转译为"前路宽"
   - D10.9 人生改变 + D12.6 家庭跑——**入门冲击力反而最强**（刚减重30斤、第一次亲子跑）
   - D12.1 极端天气 + E2 压线英雄——首次雨战即"风雨同行"，把"差点没完赛"翻译成"压线英雄"

6. **隐藏空槽**：高阶生理/生物力学指标对无数据用户**完全隐藏**（不显示"暂无数据"空槽，避免制造焦虑）。

7. **第一场即郑重供奉**：首马故事(D2)、首次里程碑(D10.6)、初心采集(D10.4)在完赛第一屏全屏庆祝——契合"第一屏先庆祝"铁律。

# Runprint 三大可跟踪子系统 + 统一游戏化层 · 定稿

> 一句话总纲:**装备(D3)/训练(D6)/餐饮(D8)统一在「我的角色面板 / My Loadout」一个 RPG 化心智容器下，但各自是独立可跟踪的一等公民子系统。三者的交汇点是「单场 Loadout 快照」——挂在每条 Finish 上，把抽象画像维度落成"绑定具体战役的真实配置"。统一铁律一条：游戏化只显影真实努力，买不到、刷不出、不羞辱人。**

> 视觉语言铁律(继承 Field Archive)：**深绿=底(沉淀)/ 完赛金=荣誉峰值(段位·邮戳·稀有·传说)/ 窑火橙=唯一行动(保存·发布)**。游戏化件统一用金、用印章、用桂冠——不用霓虹、不用弹窗、不用数值飘字。看起来像一本会成长的烫金档案册，不是网游 HUD。

# 第一部分 · 装备槽位系统（D3，重点定稿）

## 1.1 设计哲学

跑者对装备的情感真实、高浓度，但散落无处沉淀（跑鞋寿命没人记、破三战靴的故事只活在记忆里、"大神这场穿什么"是跑圈最高频问题）。**装备栏 = 把这些已存在的情感和真实问题，给一个会成长、可炫耀、可参考、可留存的容器。** 借 RPG 装备栏的"形"（满足感），弃其"魂"（氪金）——所有稀有/传说由真实世界事实赋予，凡是能用钱在 App 内买到的游戏化一律不做。

对齐画像三用法：**晒**（传说战靴 + loadout 露出海报）· **参考**（同槽位看别人用什么）· **留存**（战靴进化史 / 退役墙）。

## 1.2 完整槽位地图（4 大类 → 槽位）

```
跑者装备栏 GEAR LOADOUT
│
├─ A. 战靴库 FOOTWEAR（独立成类——第一装备，数据&情感最重）
│   ├─ A1 竞速槽（碳板/竞速鞋）      ← 可多双在役 + 一件"主力"高亮
│   ├─ A2 日常训练槽（缓震/慢跑鞋）   ← 可多双在役
│   └─ A3 越野槽（越野跑鞋）         ← 多槽（不同地形）
│
├─ B. 穿戴装 APPAREL & WEARABLES（人形装备栏主体）
│   ├─ B1 跑表 / GPS              ← 核心数据源(桥接 D6)，强社交货币
│   ├─ B2 心率带 / 功率计
│   ├─ B3 上衣 / B4 下装 / B5 压缩腿套 / B6 跑袜
│   ├─ B7 头部(帽/头巾/发带) / B8 墨镜 / B9 手套·臂套
│
├─ C. 补给 / 赛事装 RACE KIT（比赛日专属，绑定单场快照）
│   ├─ C1 号码布 BIB             ← 每场唯一，强凭证感(自动绑赛事)
│   ├─ C2 补给携带(腰带/水壶/软水袋/越野背包)
│   ├─ C3 能量补给(胶/盐丸/咀嚼片) ← 桥接 D8 餐饮
│   ├─ C4 手机臂包·腰包 / C5 耳机·骨传导
│
└─ D. 战利品 / 收藏 TROPHIES（不可穿戴，进陈列柜不进装备栏）
    ├─ D1 奖牌 MEDALS            ← 已有奖牌墙心智，硬通货
    ├─ D2 完赛服 / D3 完赛证书·号码布存根 / D4 签名·合影·名场面
```

**四条结构主张：**
1. **战靴单独成 A 类**——数据浓度（里程/磨损）、情感浓度（破三战靴）、参考价值（大神同款）都远超其他装备，给头等舱。
2. **槽位"可多在役"而非 RPG"一格一件"**——真实跑者有"竞速鞋柜"，强行一格一件失真。多件在役 + 一件主力高亮。
3. **C 类是"比赛日临时 loadout"**——号码布/当天补给不是常驻装备，是绑定单场比赛的快照。
4. **D 类不可穿戴**——已凝固的荣誉进"陈列柜/战利品库"，对应 RPG 成就库。

## 1.4 比较机制（参考用法核心，从私密到公开渐进）

**① 跟自己历史比 — 战靴进化史**：横向时间轴串起槽位用过的所有鞋（"2019国产入门 → 2021 Vaporfly → 2024 Alphafly 破三"），每双标里程/见证PB/退役原因。本身就是一张可晒的"进步可视化"图。跑表/心率带迭代史同理。

**② 跟别人同槽位比 — "大神这个槽位用什么"**：
- **分布视图（不是排行榜）**："破三跑者的竞速鞋分布""跑过柏林的人这槽位 TOP5"——回答真实问题，不制造攀比。
- **指定对标**：访问公开主页可"和 TA 比装备"，看大神某场完整 loadout（参考用法杀手锏）。
- **克制红线**：不显示价格、不显示装备评分/战力值。只回答"用什么"，不评判"谁更强"。

**③ 装备图鉴收集度 Gear Codex**：网格图鉴，拥有的点亮、未拥有的灰显剪影。维度示例：碳板鞋图鉴、六大满贯完赛服图鉴、奖牌图鉴。**度**：只记录真实拥有过的，灰显=未拥有而非"欠缺"，不诱导集齐，收集度是副产品不是 KPI。

  model?: string;

  isPublicOnPoster: boolean;   // 海报露出开关(默认折叠)

interface LoadoutSlotEntry {
  slotId: string;
  itemId?: string;             // 引用 GearItem
  quantity?: number;           // 补给类(胶×4)

# 第二部分 · 训练子系统（D6）

> **定位铁律**：D6 是画像一维，不是教练工具。焦点永远是"完赛生涯"，训练是为生涯供能的私域透镜。**绝不重做日常训练记录（不抢 Garmin/Coros）、不开课表、不做训练 feed、不做练量排行榜。** 心智差异：Strava 是"我今天练了什么"（activity-centric），D6 是**"我为这块奖牌，练成了什么样的人"（career-centric）**——每段训练都溯源回它服务的那场比赛。

## 2.1 维度清单（5 子模块 + 备赛周期容器）

| 子模块 | 子属性 | 来源 | 公私 |
|---|---|---|---|
| **D6.1 训练负荷与容量** | 周/月跑量、**生涯总跑量**、急/慢性负荷、负荷比(>1.5预警)、单调度 | 手表 / **完赛反推(粗)** | 私域 + 总里程可显影 |
| **D6.2 训练结构占比**(最懂行) | 强度分区(Easy/Tempo/Interval/Recovery)、配速直方图、质量课次数、长距离频次 | 手表 | 私域 + 结构可授权显影 |
| **D6.3 生理能力指标**(身份硬证据) | **VDOT/跑力**、VO2max、乳酸阈配速、最大/静息心率、HRV、心率区间 | **完赛反推VDOT(P0可做)** + 手表 | 雷达可显影(无数字) |
| **D6.4 跑姿与效率** | 步频、触地时间、垂直振幅、左右平衡、跑步功率 | 手表 | **纯私域，不进任何对外画像，不做雷达** |
| **D6.5 连续性与交叉训练** | **周粒度**连续训练、力量/骑行/游泳次数、**伤病/康复手动标记(灰色断档非失败空洞)** | 手表/手动 | 私域 |

**备赛周期 Race Block（最重要的结构创新，把训练折叠进完赛叙事）**：
一段训练自动/手动归集成"备赛周期"，挂载到它服务的那场 Finish。`RaceBlock = {目标赛事 + 周期起止 + 总量/结构/峰值长距离/taper}`。单场完赛档案里多一块"备赛回顾：这块奖牌，你练了 16 周、跑了 720km、最长拉到 32km、最后两周减量"。**克制表达**：不叫"副本"叫"备赛周期"，不叫"通关"叫"周期完成度"。这让训练数据天然有归属和终点，避免"无尽训练日志"的虚无。

## 2.2 游戏化成长视角（能力雷达 / 技能）

**✅ 适合（显影真实积累）：**
- **能力雷达图（旗舰可视化）**：3–5 轴（速度/耐力/恢复/全面度），把训练折叠成"能力指纹"。是镜像不是奖励——如实显影你偏速度还偏耐力，不评判好坏。**克制**：≤5 轴、不打分（用"速度:偏强"不用"速度87分"）、新人轴线短不羞辱。与 D3 装备、D4 标签构成"视觉指纹三件套"。
- **三条能力成长线（技能树克制版）**：速度线/耐力线/恢复线，用进度叙事而非等级标签（"你的耐力线从'半马级'走到'全马级'"）。复用 framework"距三级差4分钟"的进度措辞语法。
- **累计里程"生涯活数字"**：单调递增，与 D3 战靴里程同构，轻里程碑（跑了几个赤道），**只在用户主动看时显影，绝不推送催促**。
- **备赛周期完成度**：副本进度的体面化，完赛即闭环，可在海报叠一行"为这一场，16周/720km"。

**❌ 过头（违背智者品牌）：** XP/LV.42 虚拟等级（与田协官方等级语义打架）· 日粒度 streak + 断签惩罚 · 练量排行榜/训练PK · 虚拟道具/氪金 · 廉价 badge 满天飞 · AI教练/课表推荐。

> **一句话拿捏**：Runprint 游戏化是"照镜子"不是"发糖"。镜子里是你真实练成的样子，看清自己产生的成就感是 Sage 式、耐用的；发糖式 XP/badge/streak 是 Hero 式、会贬值的。**只做镜子。**

## 2.6 参考价值（"参考别人怎么练"，D6 最有战略想象力的部分）

1. **结构对标**：点进比你快一档的跑者，高亮训练结构差异（"他间歇占比7%，你2%"）。**事实并陈，不开课表，只镜像不指导。**
2. **同档位训练分布（匿名聚合）**："破三跑者训练结构通常长这样"，复用 D1 三轨"导入样本自建分布"的同套数据资产。
3. **训练相似度连接**：把训练结构相似度做成新的连接维度（补充现有"同场/同城/标签"三种），练法相似的人是天然跑搭子。

> 战略价值：资深跑者最想偷看的从来不是别人跑了多少公里，而是"那个比我快的人到底怎么练的"。这个"训练方法透明度"全网无人干净拥有——这正是 Sage 品牌该有的"参考"价值：不打鸡血，给真相。

**强参考价值的关键设计——系统自动算"补给率(g/h, mg/h)"并语境化**（把"吃了啥"升维成专业情报）：
- **碳水摄入率(g碳水/h)** 是当今马拉松补给核心 KPI，自动算 + 给语境带：
  - 30–60 g/h = 保守/大众区 | **60–90 g/h = 精英主流区(破三典型)** | 90–120 g/h = 高摄入需训练肠胃区
- 直接镜像 D1"成绩要语境化"共识：两份"喝了能量胶"的方案，72g/h 和 40g/h 是完全不同的情报。
- 钠率/液体率/咖啡因总量同理。**展示形态**：横向补给时间轴图（0→42.195K，图标标补给点），下方三仪表——一截图能发小红书的"补给作业"。

**配方系统三动作**：① 保存(命名+自动属性词条) ② **复用/克隆**(下场一键调用上版微调，第二场起几乎零录入——降录入摩擦的核武器) ③ 绑定赛事+赛后回填效果，形成"方案→结果→迭代"闭环。**版本化(v1/v2/v3)** = 补给方案进化史 = 成长可视化。

**N2 本土化关键**：carb-load 主食给中式选项（白米饭/年糕/麻薯/白馒头），不只意面——这是"懂行"且国内独有的体贴。

## 3.3 参考价值设计（"破三大神赛中怎么补给"，D8 杀手锏）

- **配方绑定效果**（让方案"被验证过"）：赛后回填结构化评价 `[全程稳定无掉速][30K掉速·疑似能量不足][PB达成✅]` → 配方带"在 XX 跑出 3:28，全程稳定"实战背书，从"建议"变"被验证的情报"。镜像 D1"成绩要含金量背书"。
- **不做榜单不做排行**，做**"按目标成绩筛选的配方参考"**（我想破330，看跑进330的人用了什么补给率）。
- **去身份化聚合参照**（最安全最懂行）："跑进3小时的跑者，赛中碳水率中位数 78g/h，钠率 550mg/h，咖啡因 80% 使用"——群体智慧，不暴露任何个人。
- **收藏与对比**：⭐收藏别人公开配方进"灵感库"；**对比视图**把 2–3 份配方并排（自己 v1 vs v2，或自己 vs 公开参考），时间轴叠加、属性词条对照。
- 增长期：邀请签约跑者/赞助品牌发**官方公开配方**，是内容引擎也是 B 端变现接口（能量胶品牌天然金主）。

## 3.4 轻量录入（把摩擦降到地板，全程零自由文本）

| 手段 | 做法 |
|---|---|
| **预设模板库** | 内置 5–8 套专家预设（"全马保守区60g/h""全马精英区80g/h""炎热高钠版"），新用户选最接近的改几个数完工 |
| **产品库(带品牌)** | 内置 GU/SiS/Maurten/盐丸常见产品，选产品**自动带出每包碳水/钠/咖啡因**，系统替他算 g/h |
| **时间轴快捷模式** | "每45min一胶+每小时1盐丸"周期规则一键生成整条时间轴 |
| **配方克隆** | 第二场起克隆上场改2个数即可 |
| **流派标签先行** | N4 纯标签单选，10 秒填，作为 D8 轻量入口 |

# 第四部分 · 统一游戏化层

> 总判据：每引入一个机制，过三问尺子，全过才做——**真实性**(显影真实事件还是凭空发明？)、**凭证性**(让别人更看懂你，还是只让本人爽？)、**体面性**(吸引新人向上还是比下去羞辱？)。这把尺子就是智者品牌的克制落到游戏化上的展开。

## 4.1 用 / 不用机制清单（统一判定）

| 机制 | 用/不用 | Runprint 化（怎么用） |
|---|---|---|
| **等级/段位** | ✅ 用其形弃其魂 | **只用真实田协等级**（官方背书、买不到、Strava 复制不了），**绝不自创 XP/Lv.99**。三层渐进披露(庆祝层折叠等级→"距三级差4分钟"进度措辞→资深一键展开三轨)。视觉=桂冠徽章(金/银白/古铜) |
| **收集图鉴** | ✅ 第二核心 | 赛事邮戳册 + 城市足迹图鉴 + 装备图鉴 + 自定义收集集。**填充物必须是真实完赛**，空格=还没跑过，缺口压力指向"再去跑一场"不是"再来App一次"。邮戳永久有效，**不做限时收集** |
| **稀有度** | ⚠️ 重定义 | **稀有度=现实达成难度不是掉落概率**（波马邮戳天然稀有因为要BQ；跑了800km的鞋比开箱稀有）。用烫金+桂冠层级表达，**不做抽卡/开箱/给真实装备打虚拟品质评分** |
| **套装/成就** | ✅ 限量 | 做"有限荣誉集"(六大满贯/百马/一城一证/BQ)不做碎成就；**全产品成就集≤12个**，每个必须跑圈公认；套装"加成"=解锁稀缺显影(专属海报版式)，**不是数值加成** |
| **对比/排行** | ✅对比 / ❌公开排行 | 与自己历史比(主力)、与群体分布比(百分位"前X%"陈述句)、与某人1v1比(双方opt-in默认关)；**全站公开实时排行榜=红线绝不做** |
| **进度条/缺口** | ✅ 留存核心 | "距下级差X""百马38/100""战靴420/500km""今年还差2城点亮华东"——下一格永远指向真实跑步行为或装备自然消耗，**不指向充值/签到** |
| **解锁/里程碑** | ✅ 表达层 | 解锁的只能是"更好的凭证表达"(稀缺海报版式/桂冠认证戳)，**绝不能解锁/购买等级·段位·百分位·成就本身**——这些只能跑出来 |
| **Loadout 快照** | ✅ 核心容器 | 三子系统交汇点，见第一部分 1.6；**绝不给装备战力总分** |
| 开箱/入役仪式 | ✅ 轻 | 新装备"入列"简洁动效，一次性无轰炸 |
| 能力雷达/成长线 | ✅ | D6 旗舰，照镜子非发糖 |
| 配方书/配装复制 | ✅ | D8 核心，必须授权可见才可克隆 |

## 4.2 红线清单（宪法级，做了就背叛品牌、自毁护城河）

1. ❌ **氪金买等级/段位/百分位/成就** —— 任何凭证只能由真实成绩产生，买等级=伪造身份=摧毁可信护城河
2. ❌ **虚拟道具/抽卡/开箱/盲盒/皮肤掉落** —— 任何含"运气/付费随机"的机制
3. ❌ **给真实装备发明"战力评分/装备总分"** —— 既伪造又羞辱（尤其对国产/入门装备）
4. ❌ **公开实时排行榜** —— 制造焦虑、羞辱后排、逼出刷榜、与低频生涯心智冲突
5. ❌ **廉价徽章轰炸** —— "首次打开/完善资料/分享第一张/连续登录"等把"用App行为"伪装成"成就"
6. ❌ **签到/打卡/每日任务轰炸** —— 低频产品做日活=反品牌、逼出假日活（NSM 已弃用 DAU）
7. ❌ **把入门跑者比下去羞辱** —— 绝不显示"未评级/入门级/倒数第N"，一切用渐进披露+进度措辞+正向百分位切片；**完赛第一屏永远是庆祝**
8. ❌ **限时 FOMO 收集** —— 与"终身资产"心智冲突
9. ❌ **装备/补给导购轰炸** —— 显影"你已有的"，绝不沦为"推销你没有的"（中立是聚合全量数据的前提）
10. ❌ **D6/D8 把私域数据强推上公开主页** —— 训练负荷/HRV/体重永不上脸

## 4.3 如何统一在"角色面板/loadout"心智下且不违背智者品牌

**核心机制：一条"真实努力 → 显影"的单向阀。**

```
真实事件(完赛/里程/训练/补给) ──[只进不造]──▶ 显影(段位/邮戳/loadout/雷达/海报)
        ▲                                              │
        │            ❌ 绝不存在反向箭头                  │
        └────  钱 / 时间 / 运气 都买不到上面那一格 ────────┘
```

- 段位是**跑出来的**(田协官方)、邮戳是**完赛盖的**、战靴里程是**磨出来的**、雷达是**练出来的**、配方是**验证过的**。能花钱的**只有"显影的精致度"**(稀缺海报版式)，永远不是"显影的内容真实性"。
- **游戏化的"强度"本身渐进披露**：新人看到的是一本温柔的纪念册，资深看到的是一套硬核身份引擎——同一引擎三套默认权重。**这是调和"强游戏化"与"智者克制"的总开关。**
- **防沉迷结构性保证**：所有进度条/缺口的"下一格"都指向**线下真实行为**（再跑一场、换双鞋），没有一格指向"再打开App/再充值"。Runprint 故意不闭合 App 内闭环——它永远把你推回赛道。

## 4.4 统一视觉语言（档案绿对游戏化的驯化）

| 机制 | 档案绿表达 | 复用资产 |
|---|---|---|
| 等级/段位 | 桂冠徽章(金/银白/古铜金属) | 段位桂冠系统(01 §三) |
| 收集图鉴 | 城市邮戳(城市+年份+距离印章) | 赛事邮戳子系统，②足迹 |
| 稀有度 | 烫金+桂冠层级(普通暖米纸单色/稀有完赛金烫金/顶级金桂冠) | 完赛金 #D6A553→#F7BD72 |
| 成就/套装 | 集齐解锁专属海报版式+主页桂冠 | ④显影 |
| 进度条/缺口 | 苔绿数据高亮 #8BC34A | 次强调苔绿 |
| loadout快照 | 档案卡质感(暖米纸底+等宽成绩数字) | tabular figures |

> 视觉度：**用金不用霓虹、用印章不用弹窗、用桂冠不用数值飘字。** 整套看起来像一本会成长的烫金档案册，不是网游 HUD——完赛金是情绪峰值唯一信号色，让游戏化高光自然收敛；游戏化件绝不抢用橙色（避免与"行动/变现"混淆）。

- D8：配方绑定真实赛事成绩 → "被验证的情报"含金量背书

# 第六部分 · 需创始人拍板的分叉

**① 装备录入靠手动会不会太重？（最关键）**
- 现状：P0 装备里程靠手动（手表自动累加要等 D6 在 P1 才落地）。手动录入"今天穿哪双鞋"是持续摩擦点。
- 推荐：P0 接受手动兜底（F6 已锁轻量版），但**里程自动化的优先级要前移到 P1 第一批**——它是装备系统"会成长"的命门，纯手动里程长期会被弃用。
- **拍板点：P0 是否接受"装备里程纯手动、可能不准"作为已知妥协，还是把 D6 手表对接（至少里程同步）提前到 P0 末期与装备一起上？** 这决定装备系统 P0 的"活体感"成色。

**② 手表对接优先级？**
- D6 整体后置 P1+，但"手表里程同步"同时服务 D3 装备自动累加 + D6 训练，是**两个子系统共享的基础设施**。
- 推荐：P0 提前排队申请 Garmin/Coros 开发者准入（周期以月计，不抢早会卡住 P1）；授权流实现放 P1。
- **拍板点：是否现在就启动 Garmin/Coros 开发者准入申请（只占法务/BD 资源，不占工程），以免 P1 卡在准入？** 以及 framework 4.3 的前置假设——"需先验证用户愿授权日常数据"——是否用 P0 占位入口埋点先测。

**③ 餐饮要不要做？做到什么程度？**
- D8 翻盘逻辑成立（破三人群把补给当军备机密、是"参考"王炸、西方竞品空白），但确实是三者中价值最窄、最进阶向的。
- 推荐：**P0 只做 N4 流派标签（10秒填、并入 D4、零成本有炫点）+ N1 配方数据模型预留**；完整 D8 放 P1，作进阶跑者深度护城河。
- **拍板点：认不认 D8 从 later 翻盘为 P1 一等公民？** 还是维持原判断"D8 永远 later"、P0 连流派标签都不做？这是"是否押注进阶跑者深度留存护城河"的战略选择。

**④ Loadout 快照在 P0 做到多完整？**
- 它是三子系统交汇点 + 强社交货币，但完整版（鞋+表+号码布+补给+配速+天气）依赖 D6/D8 都上线。
- 推荐：**P0 做极简版（仅鞋+奖牌+号码布，绑 Finish + 海报露出）**，D6/D8 上线后槽位渐次填满。
- **拍板点：P0 的 loadout 快照是只挂"鞋+奖牌"两槽极简版，还是预先把 5–6 槽 UI 都铺好（即便补给/训练槽暂时空着占位）？** 前者轻、后者给用户"面板会长满"的预期。

**⑤ 游戏化"角色面板剪影"用不用拟人形象？**
- 角色面板视图的"抽象跑者剪影"是 RPG 即视感的来源，但拟人剪影有调性风险（可能滑向廉价游戏感，与智者克制冲突）。
- **拍板点：角色面板用"拟人剪影环绕槽位"（强 RPG 感、强满足感）还是"纯档案卡网格"（更克制、更档案绿、弱 RPG 感）？** 这是"游戏化满足感 vs 智者克制"在 UI 形态上的具体取舍。

**一句话给创始人**：装备/训练/餐饮统一进"我的角色面板/loadout"一个 RPG 心智容器、各自独立可跟踪，交汇于挂在每条 Finish 上的单场快照；整套游戏化用一条铁律驯服——**只显影真实努力，买不到、刷不出、不羞辱人，能买的只有海报精致度**。P0 = 装备战靴库轻量版(F6) + 奖牌 + 极简 loadout 快照；D6 训练只留三张空表+复用 VDOT+占位入口测授权意愿；D8 餐饮只上流派标签轻钩子+预留配方模型。视觉全收进档案绿"烫金档案册"语言（金=荣誉、印章=收集、桂冠=段位），看起来像一本会成长的证书，而不是网游面板——强游戏化恰成智者品牌"看清自己、压得住场子"的最佳载体。
