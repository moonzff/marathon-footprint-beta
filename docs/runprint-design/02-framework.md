# Runprint P2 框架方案

> 从六路发散到一套定稿。一句话总纲：**Race 是护城河的物理交点，海报与画像是两个公共齿轮，导入摩擦是唯一的生死开关。** 整套框架围绕"导入 → 显影 → 晒 → 被看见 → 再导入"这一条飞轮收口，其余皆为供能。

## 一、产品核心模型（定稿）

### 1.1 对象关系（七个核心对象，一句话定稿）

```
                    ┌──────────┐
                    │  Runner  │  身份锚点
                    └────┬─────┘
        ┌────────────────┼────────────────┐
     1:N│             1:1│             1:1 │
   ┌────▼────┐      ┌────▼────┐      ┌────▼─────┐
   │ Source  │      │ Career  │◀─────│ Profile  │ (计算产物·带版本)
   │ 来源凭证 │ OCR  │  生涯   │ 聚合 │ 9维画像   │──▶ Grade(可空)
   └────┬────┘ 去重 └────┬────┘      └──────────┘──▶ TrackScore三轨
        │   N:1          │1:N                       └──▶ Quest收集
   ┌────▼────────────────▼────┐
   │   ★ Finish 完赛记录 ★    │  系统唯一原子事实·唯一带验证态
   └────┬────────────────┬────┘
     N:1│             N:N │
   ┌────▼────┐      ┌────▼────┐
   │  Race   │      │  Quest  │
   │ 赛事字典 │ ◀── 共享字典：去重×百分位×社会图谱的物理交点
   └────┬────┘
        │ Stage层基于Career/Finish生成
   ┌────▼─────────┐   ┌──────────────┐   ┌────────────┐
   │  Artifact    │──▶│ PublicProfile │──▶│ Connection │
   │  显影海报      │   │  公开主页      │   │  轻连接     │
   └──────────────┘   └──────────────┘   └────────────┘
```

**三条结构性铁律（工程地基，不是 UI 补丁）：**

1. **Finish 是唯一原子事实，且只有它带验证态。** Career / Profile / Artifact 全是派生物，永远可由 Finish 全量重算——这是"可信"护城河的工程地基，任何一条成绩都能溯源到 Source 凭证。
2. **Race 是跨跑者共享的字典实体，不是 Finish 的私有字段。** 它同时喂养「去重精度（聚合）」「群体百分位与可信度（身份）」「同场社会图谱（连接）」——**Race 是聚合×可信×身份三者咬合的物理交点**，工程资源优先压在这里。
3. **Profile / Grade / TrackScore 是计算产物、带版本号，`Grade = nullable`。** 等级可空与渐进披露在数据模型层就支持，算法迭代时全量重放事件刷新，无需迁移。

### 1.2 三层架构（单向依赖，上层只读下层）

```
┌────────────────────────────────────────────────────┐
│ L3 The Stage 表现/分享   海报·主页·同城发现            │ ← 重美学·轻社交
└──────────────▲─────────────────────────────────────┘
               │ 只读「数据骨架」+ 用户自传照片
┌──────────────┴─────────────────────────────────────┐
│ L2 The Engine 画像/计算  Career·9维Profile·等级·三轨   │ ← 可重放·带版本
└──────────────▲─────────────────────────────────────┘
               │ 只读 Finish 事实流 + Race 字典
┌──────────────┴─────────────────────────────────────┐
│ L1 The Ledger 数据/聚合  OCR·去重·实体解析·验证态机     │ ← 最难·最值钱
└────────────────────────────────────────────────────┘
```

三层一一对应三支柱（Ledger / Engine / Stage），与 P1 概念骨架严丝合缝。渲染与计算解耦：Artifact 只消费数据骨架，照片只来自用户自传——美观海报是亮点，但绝不污染数据层（对齐肖像权红线 Crux 7）。

### 1.3 主链路（一条事件驱动的链式反应）

```
[上传成绩单截图 / 授权导入]
   │
   ▼ ① 采集(L1)  生成 Source 凭证，原始图绝不丢
   ▼ ② 实体解析(L1)  Race 字典匹配/建候选 + Runner 确认
   ▼ ③ 去重(L1) ★关键闸门★  指纹=(Runner×规范化Race×日期×距离)
   │      命中→合并来源、提升验证态(多源交叉=更可信，不新增、不删)
   │      未命中→创建新 Finish
   ▼ ④ 落库(L1)  写 Finish 事实流，Source↔Finish 建溯源链
   ▼ ⑤ 重算(L2)  Finish变更→Career重聚合→9维Profile→Grade→三轨→Quest
   ▼ ⑥ 显影(L3)  数据骨架+自传照片+模板→渲染 Artifact
          第一屏永远先庆祝完赛，等级渐进披露（新人不显未评级）
```

**链路主张：** ②③ 之间是壁垒所在——国内无统一 API，OCR 必带噪声（枪声/净成绩、赛事别名），去重必须用指纹而非字符串相等，**Race 规范化质量直接决定去重质量**。低置信度字段进**人工确认队列**（"确认这场成绩"卡片），把模糊性显式交还用户，既提质量又强化"账本是你的"心智。⑤ 幂等可重放，算法升级重放全部事件即可全量刷新。

## 二、信息架构（定稿）

### 2.1 底部 5 Tab：保留栏位数，换轴心对齐三支柱

> 7 个原型页是功能清单，不是导航。直接做 7 Tab 会犯两个错：底栏挤、且把"画像/海报/发现"这种结果型/动作型页面误当并列内容仓。

| # | Tab | 内核 | 装什么 | 支柱 |
|---|-----|------|--------|------|
| ① | **印记** | Home | 最新完赛庆祝卡 + 生涯快照 + 等级进阶 + 收集任务 + 导入CTA | Engine 门面 |
| ② | **足迹** | Map | 城市足迹地图 + 单城邮戳 + 收集册 + 海外背景图层 | Ledger 空间视图 |
| ③ | **生涯** | Ledger | 完赛账本列表 + 单场档案/纪念册 + 九维画像全展开 | Ledger+Engine 主体 |
| ④ | **显影** | Stage | 海报生成 + 生涯主页海报 + 年度回顾 + 发布画像 | **唯一 CTA Tab（橙）** |
| ⑤ | **我的** | Me | 公开主页 + 同场/同城/标签连接 + 圈层 + 设置 | Stage 连接面 |

**四条命名/降级主张：**
- **"印记"做首页，弃用"护照"**（蓝图明令、官方占名）。首页职责=完赛第一眼庆祝+平时回访钩子，是 Engine 显影门面，不是独立内容仓。
- **"画像"不开 Tab——它是透镜不是去处**，主体折叠进③生涯，三个高炫耀维上探到①首屏。
- **"海报"升格为④显影并吞掉"发布"动作**，橙色窑火唯一 CTA 锚在这里；"发布画像让人找到我"=显影后摆上 Stage，与海报同源。
- **"社区/发现"绝不设独立 Tab**（战略红线"不做重社区"）。一个叫"社区"的 Tab 会持续制造"该有 feed、该有热度"的产品压力，把团队拖向要避开的形态。降级为⑤内的横向连接。

### 2.2 一级界面地图

```
① 印记  庆祝卡 / 生涯快照条(D1·D2) / 等级进阶卡"距下级差X分钟" / 活跃状态(D9)
        / 收集任务进度 / ＋导入完赛(OCR→校对→别名匹配→入账本，命脉入口)
② 足迹  城市足迹地图(D2主场) / 单城邮戳→该城完赛 / 收集册(六大·一城一证·百马) / 海外图层
③ 生涯  完赛账本(筛选:年份·距离·赛事)→单场档案(成绩·证书·纪念册·＋生成海报)
        / 我的画像(9维聚合页:首屏D1三轨·D2履历·D9 + 折叠D3·D4·D6·D8·D5明细)
④ 显影  完赛海报生成 / 生涯主页海报"我跑过的N场一张图" / 年度回顾汇编 / 发布画像→公开主页链接+"让对的人找到我"开关
⑤ 我的  我的公开主页 / 连接(同场跑友·同城·标签发现) / 圈层跑团(D7) / 设置(隐私·验证D5·授权)
```

### 2.3 个人画像主页首屏层级（对外公开主页）

服务两类观众：**自己回访炫耀 + 被发现者 3 秒判断"是不是对的人"**。

```
┌─ 首屏（无需滚动）─────────────────────────────┐
│ 1. 身份头条：昵称+头像+风格标签(D4×3)+田协桂冠徽章(有则亮，无则隐) │
│ 2. 生涯三连数(最硬社交货币 D1+D2)：完赛N场·M城·X年跑龄          │
│    + PB全马X:XX:XX（同群体百分位 ✓已验证）                      │
│ 3. 最新/代表完赛卡（一张，带城市邮戳）                          │
│ 4. 城市足迹缩略地图（D2 点亮城市）                              │
└──────────────────────────────────────────────────────────┘
┌─ 下滑折叠 ─ 收集册徽章墙 / 战靴库(D3横滑) / 完赛时间线 / 圈层(D7) / [连接·仅本人可见] ┐
```

**层级铁律：** 首屏唯一目的=3 秒回答"多能跑、跑过哪、什么风格"；**等级徽章渐进披露——有就亮，没有绝不留空位羞辱新人**；首屏素材只用自传/赛事授权（肖像权红线）；**D6 训练 / D8 补给不进公开主页**（私域透镜，留在③生涯自我视图）。

**9 维落位一句话规则：** 首屏=让你想晒的（D1/D2/D9）；折叠=让懂行人点进看的（D3/D4/D6/D8）；贯穿=让一切可信的（D5，以小徽章✓贴在每场成绩/每张画像上，不独占版面）。

## 三、核心闭环（定稿一张图 + 两个生死点）

```
                          ┌──────────── 裂变环 ────────────┐
                          │  海报带城市邮戳水印(品牌+归属人+主页短链) │
                          │         ↓ 晒到小红书/朋友圈            │
                          │  他人看到 → 扫码进【公开主页=落地页】    │
                          │  免登录先看到真实跑者精彩画像           │
                          │  "生成你的跑步显影→" 病毒钩子 → 注册     │
                          └───────────────┬───────────────────┘
                                          │ 拉新（K因子）
   ┌──────────── 主价值环（增长飞轮）──────▼──────────────────┐
   │  导入完赛 ──► 画像即时变化 ──► 峰值自动推海报 ──► 用户一键发布  │
   │   (L1脏活)    ★生死点②画像活★   ★生死点①海报惊艳★            │
   │      ▲                                          │          │
   │      │ 反复推回"海报段"                            │          │
   └──────┼──────────────────────────────────────────┘          │
          │                                                     │
   ┌──────┴──────────── 留存环（对抗低频季节性）───────────────────┘
   │  生涯增厚(单调递增资产) + 收集册缺口压力(蔡格尼克)            │
   │  + 赛季回访(报名季召回·撬真实报名·优先级最高)                │
   │  + 年度回顾(全年沉默用户强召回·裂变高峰) + 活数字浮动         │
   │  每个机制终点都"喂回画像内核" → 出口直接接回主环海报段        │
   └────────────────────────────────────────────────────────┘
```

**三环如何咬合（一句话收口）：** 主环产生分享物（海报），裂变环把分享物变拉新，留存环把存量用户在非赛日留住并**反复推回主环海报段**。两个生死点是**公共齿轮**——海报同时是主环出口/裂变载体/留存产物（年度回顾），画像同时是主环中枢/留存内核/裂变落地页内容。

### 两个生死点 + 对策

| 生死点 | 是什么 | 对策（保命设计） | 红色警报指标 |
|--------|--------|------------------|--------------|
| **① 海报必须惊艳到「自发晒」** | 裂变总闸：不惊艳→0分享→拉新归零→飞轮只剩留存内耗 | 峰值时刻**自动生成并推送成品**（创作门槛压到一次点击）；里程碑解锁稀缺版式（稀缺=晒的动机）；照片合成"美到自己拍不出"；**无照片时靠数据可视化独立成立**；水印=荣誉印记非广告 | **海报分享率**（分享数/生成数）跌破阈值 |
| **② 画像必须「非比赛日也值得回来」** | 留存总闸：只赛后有用→装了就忘→无存量承接裂变流量 | 画像是**「活数字」非静态证书**（增厚/缺口/活数字浮动制造非赛日回访理由）；**第一屏永远先庆祝、渐进披露等级**（新用户第一天不被劝退）；每次回来都有"下一里程碑还差X" | **次月回访率 / 非赛日打开占比** |

## 四、MVP / P0 边界（定稿）

### 4.1 一句话范围声明

> **P0 = 一个跑者把散落各平台的完赛截图导进来，5 分钟内得到一张让他忍不住转发的"生涯显影海报"，并拥有一个可被搜到、值得收藏的公开身份页。不变现、不社区、不训练——只证明"聚合+显影这套身份叙事，跑者认、愿意攒、愿意晒"。**

### 4.2 P0 功能清单（7 件锁定最短惊艳闭环：导入→显影→收藏→分享→被看见）

| # | 功能 | 闭环中不可替代性 |
|---|------|------------------|
| **F1** | OCR 导入 + 完赛账本（Ledger） | 护城河物理入口、唯一脏活壁垒。批量导入+字段纠错+去重 |
| **F2** | 生涯聚合视图：场次/城市足迹/跑龄/PB（D2） | 导入后即时回报，3秒"原来我跑了这么多"震撼 |
| **F3** | 三轨水平显影（D1，渐进披露版） | 区别于"记录工具"的灵魂，把成绩翻译成身份 |
| **F4** | 完赛峰值海报（Stage） | 唯一且最强自发增长引擎，无预算投放下的命脉 |
| **F5** | 公开身份主页 | 海报落地页=转化入口，没它海报只是图不是漏斗 |
| **F6** | 装备/战靴库（D3，轻量版） | 唯一低成本高传播社交货币，弱跑者也有可晒，扩大可用人群 |
| **F7** | 基础信用标识（D5，标识非核验） | 可信是支柱之一，聚合数据"看起来可信"的底线 |
| +D4 | 风格标签（自动生成、只读） | 零输入成本附带，增身份趣味+海报文案素材 |

### 4.3 P0 画像维度：做 5 维 / 后置 4 维

**做（D1/D2/D3/D4/D5）——只做"导入数据就能自动显影"的维度：**
- **D1 三轨** 渐进披露：第一屏先庆祝，三轨主动点开才显影；田协等级用规则表静态映射，跑力分用公开算法（Riegel/VDOT），百分位用导入样本自建粗分布（早期标注"估算"）。绝不把"未评级"糊脸。
- **D2 履历足迹** P0 主菜做满：场次/足迹地图/跑龄/PB墙/收集册。
- **D3 战靴库** 轻量：手动添加+标记本场+海报露出。
- **D4 标签** 自动只读：规则派生（破三选手/城市收集者/夜跑型）。
- **D5 验证** 贯穿层做"标识"不做"核验"：标来源+"自跑者授权导入"，建可信视觉语言。

**后置（需持续投入/社交训练数据回流）：** D6 训练（P1+，需先验证愿授权日常数据）· D7 圈层（P1 连接）· D8 补给（Later，价值最低）· D9 活跃（P1，需跨期数据）。

### 4.4 最 Riskiest 假设与验证法

> **🔴 假设 A（最致命）：跑者愿意忍受 OCR 导入摩擦，把分散数据搬进来。** 这是整个护城河的地基，第一步断则后面全是空壳，也是 P0 唯一必须用真实数据验证、最可能被证伪的假设。
>
> **验证法：** 盯**导入完成率 + 导入留存**——注册用户中完成≥3 场导入的比例（门槛≥40%）。**最小成本法：先不做全自动 OCR，用"OCR 预填 + 人工兜底"（后台人工帮种子用户清洗），先证明"用户愿意为聚合付出努力"，别先把钱烧在 OCR 精度上。** A 被证伪→整个产品方向重估。

（次级：假设 B 海报自发分享率足以零预算增长→埋点三段漏斗+A/B 模板，几乎零成本最早上线；假设 C 三轨"被认"不"被反感"→渐进披露缓冲+10-15 人种子定性访谈。）

### 4.5 砍到 3 件的极简版（资源不足时的退路）

**OCR 账本（F1）+ 完赛海报（F4，内含 D1 三轨+D2 足迹精华作海报内容）+ 公开主页（F5，可极简到"海报+一句话身份+导入按钮"）。** 首尾相连=可自传播最小漏斗。D2/D1 不作独立页，作为海报内容素材存在——先证明叙事打动人，再决定是否加厚画像页。唯一风险：无独立画像页留存偏低（晒完就走），这正是用极简版低成本验证 A/B 再决定是否升级到 7 件套的合理路径。

## 五、北极星 + P0 三个核心数（定稿）

### 北极星 NSM = 周活跃「显影主页」数（WASP）

> 统计周内**至少被一次外部触达**（被分享 OR 被非本人访问 OR 本人主动发布峰值物料）的**生涯主页去重数**。一周计 1，不论触达几次。

**为什么是它：** 同时锁死两个战略命门——①**画像价值**（只有账本够厚、显影够美，主页才"值得被看"，前置依赖 Ledger×Engine 扎实）；②**病毒传播**（"被外部触达"本身就是 K 因子分子）。一个数同时为"做深"和"做广"负责。不用 DAU/MAU（跑步低频季节性，日活天然假，逼出反品牌的签到轰炸）。**护栏：** 外部访问者 7 日回访为正、投诉率<0.5%——NSM 涨但护栏破=虚假繁荣。

### P0 死盯的 3 个核心数 + Go/No-Go

| # | 核心数 | 回答什么 | Go(绿) | 灰区 | No-Go(红，停下改产品) |
|---|--------|----------|--------|------|----------------------|
| 1 | **激活率**（导入≥3场+出首张海报） | 产品成不成立、Aha够不够硬 | **≥40%** | 25–40% | **<25%**：OCR太难用或显影不够惊艳，先别谈增长 |
| 2 | **赛后归档率**（新完赛14天内导入） | 是否真留存、有无习惯回路 | **≥50%** | 30–50% | **<30%**：没当账本，只玩了次海报，留存假 |
| 3 | **K 因子**（裂变系数） | 能否不靠买量自己长 | **≥0.5且升** | 0.3–0.5 | **<0.3且平**：主页/海报不够"想晒"，病毒机制没通 |

**Aha 时刻 = 导入≥3 场→聚合出生涯/画像→生成并看到第一张海报**（≥3 场才从"记一笔"跨到"生涯"）。**决策逻辑：** 三全绿→启动 P1；激活绿+归档红→回去做厚 Ledger（别急拉新）；激活归档绿+K 红→回去打磨 Stage（裂变工程问题非产品问题）；激活红→一切免谈，全部资源回到导入体验+首张海报惊艳度。

## 六、关键设计决策（7 条：核心点 + 推荐立场）

| # | 核心点 | 推荐立场 | 做错的后果 |
|---|--------|----------|-----------|
| **1** | **导入摩擦**（产品存在前提） | **单图秒入 + 分层兜底，绝不要求补全。** 摩擦前移到机器侧：宁可机器识别70%让用户一键确认，也不让用户从0填到100；空画像也能生成海报；海外/越野/小赛先用手动1行兜底，覆盖率>单源精度 | 唯一"做错=直接死"——没数据没画像，下游全建在沙子上 |
| **2** | **中立性**（护城河地基） | **对"成绩的生产与裁决"硬中立（死守），对"成绩之外的连接与服务"开放（留口）。** 永不办赛/发成绩/卖奖牌/改评成绩；中立是成绩洁癖，不是商业清教。写进宪法级文档 | 守松=变成又一个悦跑圈（慢性自杀）；守死=不可盈利（违背战略前提） |
| **3** | **信用验证** | **做"可信度分层徽章"而非"真伪二元"：🟢已核验/🔵可信(多源交叉+EXIF)/⚪自述。** 验证抬升荣誉而非设门槛，资深跑者会主动补证书点亮绿标；绝不打反PS军备竞赛，用社会成本遏制造假。P0先做🔵层（纯软件零依赖），留好🟢徽章位与算法架构 | 二元强验证→录入摩擦爆炸+误杀真成绩；零验证→画像注水、KOC不敢晒、社交货币贬值 |
| **4** | **等级渐进披露** | **用"显影深度"分层而非"是否显示"开关。** 第一屏=庆祝层（零评判）；下滑=水平层，用进度措辞"距三级差4分钟"而非"未评级"；资深可一键展开全部三轨。"朦胧不是缺陷是阶段" | 贴脸羞辱新人→增量人群进不来；藏死→资深觉得不硬核、KOC不背书。两端都得罪=最糟 |
| **5** | **海报**（唯一免费获客引擎） | **标准="不像App导出图，像可裱起来的个人作品"。** 三硬标准：信息克制(一张突出一个峰值故事)/个性显影(城市足迹形状·战靴·标签构成视觉指纹)/Field Archive档案质感。水印=荣誉印记非渠道广告（"经Runprint核验·已完赛38场"），用户晒它因为它证明了他 | 丑/俗/像运营图→0自发分发→无投放约束下获客归零，困死在种子用户里 |
| **6** | **冷启动密度** | **放弃全国铺开，采用"赛事/跑团为单位的密度爆破"。** 选1-2场赛事或5-10个种子跑团集中渗透到60%+，做出"打开同场全是我认识的人"的满员体验，再复制。KOC自带跑团=一个KOC带一个密度单元，天然适配beachhead | 全国稀疏→发现页空空→连接支柱价值无法感知→社交飞轮点不着，Stage形同虚设 |
| **7** | **合规/肖像权**（写进架构非条款） | **三条宪法级红线做进数据模型：** ①照片只接受本人上传、绝不抓取他人/官方人脸（人脸绑"上传者"）②聚合靠用户主动授权导入、绝不爬他人数据（每条数据带"授权来源"）③公开主页精确位置脱敏、被同场发现是opt-in。让违规在架构上根本发生不了 | 触法+自毁可信人设=双倍杀伤；对以"可信"为护城河的产品是声誉性死亡 |

> **补充立场（身份所有权，长期护城河）：** 把画像定位为"用户拥有、可导出、可携带的终身资产，平台是托管者不是占有者"——支持一键导出完整生涯+永久身份链接。弃用"护照"隐喻但保留其"可携带身份"内核：越允许带走，资深跑者越敢深度投入；身份链接到处贴=又一个免费分发面。建议纳入 P1 承诺，P0 先把数据模型留好导出口。

## 七、需要创始人拍板的分叉

以下四个分叉，材料各路已给出推荐立场，但属于"赌注级"决策，需创始人定调：

**① Tab 结构：5 Tab（印记/足迹/生涯/显影/我的）还是更激进的 3-4 Tab？**
- 推荐 5 Tab（保留 beta 栏位数，换轴心）。但若团队认同"P0 砍到极简三件套"，①印记与②足迹在 P0 可暂时折叠进③生涯/④显影，**P0 实际只需 3-4 Tab**。拍板点：**首版是按完整 5 Tab 框架铺，还是按极简版只上 3 Tab、验证后再展开？** 这决定首版工程量与 IA 的"承诺感"。

**② 北极星：用 WASP（周活跃显影主页）还是直接用「激活率」当首版北极星？**
- WASP 是"终态"北极星（同时管做深+做广），但 P0 早期主页基数小、外部触达稀疏，WASP 绝对值会很难看、易误导。**拍板点：P0 验证期是否先用「激活率」当作战北极星，把 WASP 留作 P1 增长期切换？** 指标体系两者都已定义，差别在"现在死盯哪个数对团队的行为牵引"。

**③ P0 砍到哪：完整 7 件套，还是极简 3 件套（OCR账本+海报+主页）？**
- 这是资源与风险的核心权衡。7 件套验证更完整但工程重、上线慢；3 件套最快验证最致命假设 A/B，但**无独立画像页，留存可能偏低（晒完就走）**。拍板点：**赌"叙事先打动人"先上 3 件套，还是赌"画像页是留存地基"直接上 7 件套？** 推荐 3 件套起步，但需创始人接受"首版留存数据可能不好看、且是预期内"。

**④ 中立性的商业边界线划在哪？**
- "对成绩硬中立、对下游服务开放"是方向，但**具体哪些下游算"开放"**（认证身份背书/装备导购/中立报名推荐位/生涯实体化年鉴）需创始人逐项拍板并写进宪法级文档。拍板点：**第一个被允许的变现口子是哪个、什么时候开**——这条线划错（太松=自杀，太死=不可盈利）是 Crux 2 的双向陷阱。

---

**一句话给创始人：** P2 框架已收口为"一条飞轮 + 两个齿轮 + 一个生死开关"——飞轮是导入→显影→晒→被看见，两个齿轮是海报惊艳度与画像活体感（P0 唯一两件大事），一个生死开关是导入摩擦（假设 A，做错即死）。其余皆为供能，Race 字典与去重引擎是最该优先压资源的战略下注。
