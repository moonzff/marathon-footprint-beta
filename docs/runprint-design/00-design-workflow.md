# Runprint 设计工作模式 (Design Working Mode)

> ⚠️ **从属关系(2026-06-19 修订):本文是 [METHODOLOGY.md](METHODOLOGY.md)(品牌与设计总纲)下、面向"阶段 3–5(视觉/系统/指南)"的任务级子流程。** 全局阶段顺序、战略先行的铁律与闸门以 METHODOLOGY.md 为准;本文只管"具体设计任务怎么执行"。
> 设计任务多、要反复迭代——先定"怎么做设计"(流程 + 工具分工 + 模板),再做具体设计。日期 2026-06-19。

---

## 0. 核心原则

1. **先 Brief 再动手**:任何设计任务,先写《设计 Brief》(背景+需求+约束),对齐了再画。
2. **比稿必附说明**:每个候选方向都要有《设计说明》(风格/思路/亮点/适用/取舍),不让创始人盲选。
3. **干跑优先**:每步先出文字/低保真预览,确认方向,再进 Figma 做高保真。
4. **Figma 是设计的家**:所有设计成果汇入 Figma 统一管理、批注、版本;对话里只做关键决策与文字产出。
5. **可追溯**:每次比稿/选择/精修都留决策记录,接 `01-foundation`(品牌锚点)。

## 2. 每个设计任务的标准流程(可复用)

```
0 设计 Brief        ── 背景+目标+受众+约束+参考+成功标准(动手前必填,对齐)
        ▼
1 设计思路/方向定义  ── 列出 N 个差异化方向 + 每个的概念与灵感
        ▼
2 比稿(并排选项)   ── 每个选项必附《设计说明》(模板 B);Figma 并排成板
        ▼
3 评审打分          ── 按标准(品牌契合/识别度/可扩展/落地难度)+ 创始人拍板
        ▼
4 深化精修          ── 选中方向迭代到定稿
        ▼
5 落地             ── 进 Figma 设计系统(tokens/组件)+ Handoff 规范
```

## 3. 模板 A —《设计 Brief》(动手前必填)

> 每个设计任务开始前,我先填这张,与你对齐后再进入比稿。

| 字段 | 内容 |
|---|---|
| **任务** | 要设计什么(如:主 logo / 完赛海报 / 公开主页 UI) |
| **背景** | 为什么做、上游依赖(接哪个文档/决策) |
| **目标** | 这版设计要解决什么、达成什么效果 |
| **目标受众** | 谁看、在什么心境下看 |
| **使用场景** | 在哪用(App 图标 / 海报水印 / 小红书 / 落地页…)、尺寸约束 |
| **战略/语言引用** | 回指《品牌战略书》《语言识别手册》《设计原则》的哪几条依据(取代预设视觉"锚点"——视觉论证必须可追溯到战略,不得预填颜色/形状) |
| **硬约束** | 必须/禁止(如避开"护照"、唯一 CTA 橙、等级渐进披露) |
| **参考与灵感** | 对标/参考方向(可附链接或描述) |
| **成功标准** | 怎样算好(如:小尺寸可辨、资深跑者愿转发、3 秒看懂身份) |
| **交付物 & 格式** | Figma frame / 设计系统组件 / SVG / 规范说明 |

---

## 4. 模板 B —《比稿设计说明》(每个候选方向必附)

> 比稿时,每个方向卡片旁/下都要有这段,杜绝盲选。

| 字段 | 内容 |
|---|---|
| **方向名** | 一句话命名(如"字标·环中字") |
| **一句话概念** | 这个方向的核心想法 |
| **风格说明** | 视觉气质、形式语言、用色用字 |
| **设计思路** | 为什么这么做、解决了 Brief 的哪个目标 |
| **核心亮点** | 1–3 个最值得看的点 |
| **适用场景** | 最适合哪些使用场景,哪些场景偏弱 |
| **取舍与风险** | 牺牲了什么、潜在问题 |
| **推荐度** | 我的倾向 + 一句理由 |

## 5. 产物与结构

**设计文档**(`docs/runprint-design/`):
- `00-design-workflow.md`(本文)· `01-foundation`(品牌)· `02-framework`· `03-profile-dimensions`
- 每次比稿/精修留《设计说明》与决策记录

**Figma 文件**「跑印 Runprint · 设计」页面结构(规范):
1. **封面** — 品牌门面
2. **品牌** — logo 定稿 / 色彩 / 字体 / 桂冠 / 邮戳
3. **设计系统** — Variables(tokens)+ 组件库
4. **比稿** — logo / 主视觉 / UI 的并排探索区(每个带说明)
5. **UI 屏** — 公开主页 / App 各 Tab / 装备栏…
6. **Handoff** — 开发交付规范

**命名 / 版本**:页面与 frame 用「类别·名称·版本」(如「Logo·环中字·v2」);定稿移入「品牌」页,探索留在「比稿」页。
